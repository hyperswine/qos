# Release modules commit cleanly again (2026-11-25)

`release.toml` lists the library modules that `fpr commit` mints on every
release. Until this change, 10 of the 18 were refused, with fprisc `151b3eeb` and
with 0.15.0 alike, so QOS could not bump its fprisc pin. Now all 18 commit, the
pin is on fprisc main (`73e8fd31`), and CI checks that every listed module still
commits.

## The refusals and their fixes

| Module | Refusal | Fix |
|---|---|---|
| `programs/mods/coreutil.fpr` | `intMax` is deprecated (Int is exact in v1.0) | `parseNat` checks against a named format bound, `natMax = 2^62 - 1`. That is the value `intMax` had, so behaviour is identical: larger input is still an `Err`, never truncated, and there is no new trap. `tests/coreutil.fpr` now uses `C.natMax` and also checks that `natMax + 1` is refused. |
| `std/blockio.fpr` (and `blockep` through it) | `handleMessage`, `pollActive` and `relayNext` are unsafe without a declared signature | Declare the `unsafe` signatures the compiler infers. They are the owner's receive/poll loop and the relay recursion, which are genuinely unbounded. Their callers were already `unsafe`, so no WCET claim changes. |
| `std/lifecycle.fpr` | Once its uses were pinned: `loopTurn` and `loop` are marked `unsafe`, but the analysis proves them safe | Drop the two markers, so the analysis now bounds them. |
| `programs/mods/timer.fpr`, `programs/mods/epservice.fpr` | The prior stored version failed today's safety lint | fprisc: `fpr commit` no longer lints the immutable prior version. Both changed their exported signatures since their last commit (#39 and earlier), so they are minted as majors. |
| `programs/mods/qlog.fpr`, `std/block.fpr`, `std/fs.fpr`, `std/lifecycle.fpr`, `programs/mods/files.fpr` (and `std/storageclient.fpr`) | Unpinned `use`s | `fpr pin <module> --deps`. Pinning to the resolved hash does not change a module's own hash. |
| `std/lifecycle.fpr` v8.0 | The prior blob does not reproduce its hash: it predates the closure rule and has an unpinned `use "std/fs"` | Minted as a major (`--major`). fprisc now names the cause instead of failing with `blob hash mismatch`. |

## The check

`sol tools/release-modules.sol check` copies the tree to a temporary directory,
runs `fpr commit` on every listed module in order, and fails if fpr refuses any.
CI runs it with the pinned compiler. When it fails, the refusal names the fix:
`fpr pin <module> --deps` for missing pins, or `fpr commit <module> --major` for a
deliberate signature break. `sol tools/release-modules.sol commit` does the same
commits in place.

## Not done here

- **Migrating off `std/actor#2de24bf2`.** `fpr pin <file> --deps --update=std/actor`
  re-pins a module and everything that cascades from it. That rewrites most of
  `programs/mods`, so it should be its own change.
- **`intMax` outside the release modules.** It is still used in 11 policy and app
  modules and 4 tests (revision counters, lease-handle wraparound). It is still
  accepted when compiling and refused only by `fpr commit`.
- **`fpr.lock`.** It was generated by the retired `qos.py lock` and is not
  regenerated here.
