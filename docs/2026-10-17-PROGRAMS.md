# Programs: confined runs, hosted apps, live checks

Date: 2026-10-17. Kind: design and implementation record. Follows
[2026-10-16-EDITOR.md](2026-10-16-EDITOR.md) and works through its "Not done"
list. The runtime half is fprisc's `docs/2026-10-17-CONFINED-PROCESSES.md`.

The Editor's Run (^R) starts the buffer as a process of its own. Until now
that process could stop QOS:

- recursing without end took its stack to the 1 GiB ceiling, then panicked;
- allocating without end met the host's OOM killer;
- `kill 5` panicked;
- `device "blk"` gave it the raw disk, under the system's own disk writer;
- ^R ended only its root actor, and the actors it had started printed to the
  host console afterwards.

It could not do much else either: no files, no keys, no screen of its own. A
mistake showed only when ^B or ^R was pressed.

## From the user's chair

- **A run is confined.** It may take a quarter of the machine's memory.
  Past that, the panel says "memory: this program's budget of N MiB is used
  up (stack overflow -- ...)" and the Editor and QOS run on. A program that
  reaches for a device ends with the device named: "blkPages (the raw disk) is
  not granted to a confined program".
- **^R stops the whole program**: every actor it started.
- **A program can be an app.** A file with an `app` (four functions over
  `std/hosted`) runs in the Editor's panel:
  - its view is the panel (12 rows);
  - it has the keys, and the panel's title says so;
  - ^J gives the keys back to the text, and back to the program;
  - ^R stops it.

  It may read and write files under `/home`, through the Editor.
- **Problems show while typing.** 300 ms after the last change (three quiet
  ticks), the buffer goes to the compiler's front end. Each error or safety
  finding is marked in the gutter (a warm bar, the line number lit). The
  header counts them, and the status line shows the one on the caret's line.
- **^R after ^B starts at once.** ^B builds a program as Run packages it, and
  the compiler server keeps that package.

## An app: `std/hosted`

```
H = use "std/hosted".
Msg = Type (Got (Result String String)).
init = {n = 0, file = "none"}.
update ev m = case ev of
    H.Key H.Enter -> ({m | n = m.n + 1}, H.readFile "/home/x.txt" (fn r -> Got r) :: Nil)
  | H.Key (H.Char "q") -> (m, H.quit :: Nil)
  | H.Msg (Got (Ok t)) -> ({m | file = t}, Nil)
  | H.Msg (Got (Err why)) -> ({m | file = strcat "refused " why}, Nil)
  | other -> (m, Nil).
view size m = (cols, rows) = size; ["n {m.n} of {cols}x{rows}", strcat "file " m.file].
subs m = Nil.
app = {init = init, update = update, view = view, subs = subs}.
```

It is the Elm shape, as `std/term` has it for a terminal:

- **`update` is a function of events.** Effects are data (`Cmd msg`), and
  their results come back as messages of the type the command promised: a
  read is a `Result String String`. A refusal (a path outside `/home`, a file
  that is not there, a host that has gone) is an `Err` in the program's own
  message. Nothing a program asks for can fail it.
- **Keys are values:** `Char "a"`, `Enter`, `Up`, `Ctrl "s"`, `Alt "x"`,
  `F 1`, never key codes.
- **Times are refined.** `after : (ms : Int | ms >= 0) -> msg -> Cmd msg` and
  `every : (ms : Int | ms >= 1) -> msg -> Sub msg`. A constant or a guard
  discharges them at compile time; the loop clamps whatever reaches it another
  way.
- **The view is lines for a panel of that size.** The loop sends a frame
  only when the lines changed.
- **One turn per message.** The loop (`host`) runs under `Sys.loop`, so a
  program that runs all day does not grow by its turns.
- **An app with no recursion of its own is a safe program.** `std/hosted` is
  on the platform's trust list (`core/trusted-modules.txt`). Its `unsafe`
  functions are the kinds already admitted: actor loops that run until
  stopped (`host`, `ticking`) and recursion over the program's own lists
  (`keys`, `perform`, `takeAsk`, `startSubs`, ...). So the program's own
  `update` and `view` stay under the safe/unsafe line: the example above
  needs no header, and a recursive helper of its own needs its
  `name : unsafe ...` signature, as anywhere. (The line is about recursion
  hidden in the program; a library loop it calls is the library's, here as
  for every trusted module.)

The name: fprisc already has `std/program` (a process's arguments,
environment and streams; QOS's `programs/liveboard.fpr` uses it). A QOS module
by that name would have hidden it from every QOS build.

### The conversation, and who checks what

```
ToHost        = Frame (List String) | Ask Int Req
ToProgram msg = Start editor cols rows | KeyIn code | Resize cols rows
              | Answer token Reply | Fire msg
```

- The Editor reads only the program's root actor (`receiveFromNow`: the
  runtime's selective receive, so no other actor can speak for it).
- Every `Ask` is checked by the Editor (`allowedPath`, `allowedPrefix` in
  `editapp.fpr`):
  - a file must be under `/home/`, not in the Editor's own records
    (`/home/.editor/`), with no `..` step, and at most 1024 bytes long;
  - a listing must be of `/home` or under it.

  A refused ask is answered at once: `Failed "/sys/files: a program may use
  files under /home only"`. A granted one goes to the app worker as the
  Editor's own file jobs do, and is answered under the program's token.
- When a program ends, its asks still with the worker are forgotten, so an
  answer can never reach the next program.
- The program holds no capability: no namespace handle, no grant. Why it is
  not simply handed the namespace: "Found along the way" below.

## Run, underneath (`programs/mods/runprog.fpr`)

`start qa budget go`:

1. `Plug.attach` the package, find its `qedRun`, and `Mod.detachLast` (a
   program is a process, not a binding).
2. `Sys.spawnApp` it under a fresh pid; it waits for its go.
3. `Sys.confine pid budget`.
4. `Sys.captureConsole pid`.
5. Send the go: `1` for a main, the `Start` for an app.

A failure after step 2 ends the pid whole (`Sys.killPid`).

`poll` returns three things:

- what the program printed since the last poll;
- what its root said, oldest first;
- whether it still runs.

When the root has ended, `poll` ends the rest of the process for the same
reason. `stop` is `Sys.killPid pid "stopped"`.

The type features carry the rules:

- **Refinements.** `Sys.confine` and `Sys.killPid` are declared in
  `runprog.fpr`:

  ```
  Sys.confine : (pid : Int | pid > 0) -> (budget : Int | budget > 0) -> Result String String .
  Sys.killPid : (pid : Int | pid > 0) -> String -> Int .
  ```

  `start`, `spawned` and `confined` carry `budget > 0` and `pid > 0` through
  their signatures. Each caller shows it with a guard, for example
  `if pid > 0 then confined h pid budget go else ...` and the Editor's
  `if budget <= 0 then Err ... else RP.start qa budget ...`. The compiler
  discharges each obligation at its guard. Pid 0, the system, cannot reach
  either primitive through Run.
- **Linear values.** A running program is `Proc 1 = Type (Proc Int Int)`, and
  a poll's verdict is `Run 1 = Type (Running Proc | Ended String)`:
  - `poll` hands the program back while it runs, and keeps it once it has
    ended;
  - `stop` takes it;
  - `tell` and `pidOf` hand it back.

  Within a function, the compiler rejects a `Proc` that is used twice, or not
  used at all. Because a model is an unrestricted value and cannot hold a
  linear `Proc` (`fprisc/docs/2026-10-17-VALUE-SEMANTICS.md`, rule 2), `open`
  spawns a process actor (`serve`) that owns the `Proc` and the console
  capture in its loop, and the Editor's model holds only that actor's address
  (`pollActor`, `tellActor`, `stopActor`).

## What a program may not do

Each refusal ends the program whole, with the capability named.

- **In fprisc's runtime** (its record lists them):
  - starting programs;
  - the interrupt router and interrupts;
  - the timer;
  - the logger's install and drain;
  - the module registry's `Mod.detachLast`;
  - killing outside itself;
  - confining or ending others.

  The system's logger is shown to it as an actor that has ended, so its
  `log` lines take C's way and appear on its own console, in the panel.
- **In QOS**, the handlers of `qos/appside/hal.c` (30) and
  `qos/appside/entry.c` (7) refuse it:
  - the machine's registers;
  - the pin bus;
  - `device`;
  - the network;
  - the raw disk;
  - sound;
  - the display;
  - the keyboard and pointer;
  - other programs' consoles;
  - the system's lifecycle (`Sys.ready`, `Sys.shutdown*`);
  - loading code (`Sys.attachImage`);
  - the host compiler;
  - the host's store.

  `Sys.timeNow`, `glHas`, `Sys.images` and `Sys.caps` are read-only answers
  and stay open.

## The budget, and ABI v22

- The HAL table gained `mem_total` (qosp: `sysconf`), the primitive
  `Sys.memTotal`.
- A run's budget is a quarter of it, or 1 GiB when the host cannot say
  (`runBudget`, `editapp.fpr`).
- As with every ABI change, a device on v21 takes qosp and every `.qa`
  rebuilt together.

## Live checks and the package cache (`tools/fprd.py`)

**The `check` op** runs the compiler's front end only: types, the safe/unsafe
line, linearity and contracts. On this Mac it takes:

- about 0.18 s for a small program;
- 0.03 s on a parse error;
- against 1 to 2 s for a package.

**How the Editor uses it:**

- It sends a program as Run would package it, so its lines map back past the
  entry.
- It keeps one check in flight, and drops an answer for an older version.
- Each answer becomes (line, column, message):
  - a parse error's location;
  - a type error's `file:line:`;
  - a safety finding, which has no location, is placed on the definition it
    names.
- Content hashes (`main@0123456789abcdef`) are dropped from the text.
- "no compiler server" turns the checks off.

**The package cache** keeps one entry per package id (`qedrun`, `qedbuild`).
Its key is a sha256 of:

- the id and the source;
- the stat of everything a build reads: the compiler, the ABI header, the
  link scripts and packaging tools, the platform's trust list, and every
  module under the import roots.

An edit to any of those misses. Measured on this Mac: 1.44 s cold, 0.01 s
cached.

**Diagnostics in the output panel** now number an excerpt line as the buffer
does: `3 | x = .` under a Run's location reads `2 | x = .`, right-aligned in
its own gutter so the caret line still points at the column.

## Bounds

Registered in [2026-09-19-BOUNDS.md](2026-09-19-BOUNDS.md):

- **A run's memory**: a quarter of the host's, or 1 GiB.
- **The package cache**: one entry per package id, the newest replacing the
  last.

The 300 ms before a live check is a time, not a bound.

## Found along the way

- **The namespace authorizes only opens** (`programs/mods/ep.fpr`,
  `epservice.fpr`):
  - `NsGrant` from any sender grants any pid anything.
  - `NsReg` claims any free url for any owner.
  - A request's sender (`from`) is the first field of a message the sender
    built. So `NsUnreg` and `NsOpen` can be sent in another actor's name. The
    reply goes to the named actor, but an open in the `replace` mode empties
    the file first.
  - The file manager trusts an `Open` forwarded to it.

  Today only system code holds the namespace's handle; handing it to a program
  would hand it all of this. That is why a program asks the Editor instead.
  The fix needs the runtime to say who sent a message, as the `receiveFrom`
  family already does for a receiver that names the sender.
- **An approved library name resolves under the platform's home first**
  (fprisc `compiler/Home.hs` `underHome`, used by `trustedLibraryPaths`). A
  QOS module at the same relative path as a reviewed fprisc std module is
  trusted under that review. This module, while it was `std/program`, was.
  Today only `std/livereload` overlaps, and QOS lists it itself.
- **A program that called `log`** was ended at the refused
  `Sys.logInstall` whenever no logger was running yet. Its lines now take C's
  way, as above.
- **`receive` is polymorphic** ("unsafe by design"), so a program can coerce
  a value to any type.
  - A primitive given the wrong type (`strlen` of an Int) now ends the actor,
    not the machine (fprisc).
  - Compiled code that matches on a wrong-typed value can still fault the
    host process.

  The Editor trusts the shape of what `std/hosted` sends. A program would have
  to coerce on purpose, for example a `view` that returns a received value.

## Not done

- **A guard-page hit is still fatal**, and so is a type confusion that
  reaches compiled code (above).
- **The namespace's authorization** (above).
- **A subscription is never stopped.** One that leaves `subs` ticks until
  the program ends: keep `subs` steady, or ignore stale ticks (`std/term`'s
  rule).
- **An app's panel is plain lines**, 11 of them under the title: no styling,
  no pointer.
- **Some keys are never an app's.** The shell keeps Esc (home) and Shift-Tab
  (focus), and the Editor keeps ^R and ^J.
- **Relative `use`** in a run still fails, as before (`std/` resolves).
- **Native QOS** has no budgets: they need the kernel's accounting.
