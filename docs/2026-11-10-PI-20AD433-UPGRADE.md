# Pi 4B upgrade to the actor round-trip runtime

Date: 2026-11-10. **Status: deployed and verified on the physical Pi 4B** (install requested by
the owner). Main, the six apps, the seed disk, the `qosp-es` host and the matching Editor SDK
now run qos `93004f8` (branch `actor-round-trip-note`, on main `4e60743`) with fprisc `20ad433`
(branch `qosapp-receive-loops`). Portable ABI 22 and codegen 204, both unchanged. Machine-readable record:
[evidence/2026-11-10-pi-20ad433-upgrade.json](evidence/2026-11-10-pi-20ad433-upgrade.json).

What this brings to the device is the runtime work in
[ACTOR-ROUND-TRIP-STEPS-2-3.md](2026-11-10-ACTOR-ROUND-TRIP-STEPS-2-3.md) and
[BOUNDED-INBOX-INLINE.md](2026-11-10-BOUNDED-INBOX-INLINE.md): the receive-loop form for app
images, the live-hart drain scan, direct handoff, and small messages (bounded or not) carried
in the ring slot. These were measured on macOS. The Pi's own round-trip numbers were not
measured in this deployment.

The method is the one in
[2026-11-06-FPRISC-PIN-TRIAL-E138E65.md](2026-11-06-FPRISC-PIN-TRIAL-E138E65.md), with its
scripts copied and re-pointed. Working files are in `.qos/validation/pi-20ad433-20261110/`
(local, not committed).

## Compatibility

- **No ABI bump.** Step 3 added a field to the runtime's ring (`ringv_t.inl`) and three
  fields at the end of the hart record. Apps and plugins call into the main image's runtime
  and never read either structure. Generated code reads hart fields at fixed offsets, and
  none of those moved.
- **Apps already on the device keep working.** User apps compiled on the device by the 6 Nov
  SDK still run: the trampoline receive form they use is still in the runtime. The 46 user
  records on the writable disk were kept.

## Rollback

```sh
/var/lib/qosp/deployment-pi-20ad433-19700110T135432Z/rollback.sh
```

It restores the 6 Nov e138e65 install and its writable disk, which discards any writes made
since this install. The Pi's clock is unset, so the stamp in the directory name is not the
real date. Three rollback directories now remain (4 Nov, 6 Nov, today's), and the root
filesystem has 285 MiB free.

Not done: the pin move (`fprisc.lock.json` on qos main is unchanged), the `fpr.lock`
fix on main, any SDK publication, and merging either branch.
