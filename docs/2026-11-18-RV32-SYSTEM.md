# System.qa on RV32: QEMU virt32 and RV32 process images

Date: 2026-11-18. Kind: implementation record, milestone M5 of the
Spectre-84 plan. Sources: QOS after `901d09b`, FP-RISC `0230c8f1` (the
software square root, below; `fprisc.lock.json` moves there).

## What changed

**An RV32 kernel build.** `make -C qos native XLEN=32 QOS_BOARD=virt32`
compiles System.qa with `--system=qos-native --target=rv32` (the M0 spike's
finding: the later option wins), links for `rv32imac`/`ilp32` (the
toolchain has an `rv32imac` libgcc multilib; `rv32ima` would silently link
the rv64 one) and runs on `qemu-system-riscv32`. `bsp/virt32` is the board:
`con0` (16550), virtio net and block. System.qa needed no source change;
the kernel is 1.20 MB of text.

**C stand-ins for the raw units.** QOS's PLIC, virtio and block-policy
drivers are FP-RISC raw library units, which lower to rv64 only. RV32 keeps
C: `plic.c` (already there) and the new `hal/virt/virtio32.c`, written from
`virtio.fpr` and `blockpolicy.fpr` line by line; `net.c` already had its own
RV32 transport. fprisc's CLINT is likewise `hal.c`'s C on RV32.

**FP-RISC: a software square root.** The runtime's `F64.sqrt` names the
square-root instruction per architecture and falls back to libm; RV32IM and
RV32IMAC have neither, so a whole-runtime link (System.qa's kernel) failed
on `sqrt`. `soft_sqrt` (`fprisc/runtime/runtime.c`) is exact and correctly
rounded on integers only: digit by digit over a 108-bit radicand with a
64-bit remainder. It matches libm bit for bit on 28 million inputs (random
doubles over the whole range, subnormals, perfect squares, integers, and
the special values). The Spectre build never hit this because it collects
unused sections.

**RV32 process images.** A process app now builds for either width
(`tools/build-process-app.sol APP MANIFEST OUT rv32`):

| Piece | Change |
|---|---|
| `tools/elf-image.sol` | ELF32 program headers |
| `tools/qa-relocations.sol` | ELF32 sections, `Elf32_Rela` (type and symbol packed in `r_info`), `R_RISCV_32` as the absolute type, 4-byte relocated words |
| `tools/qa-moved.sol` | checks 4-byte moved words |
| `tools/qa-pack.sol` | `architecture = "riscv32"` for ELF32 RISC-V |
| `loader/qaimg.c` | relocates `sizeof(uw)`-byte words |
| `tools/native-abi.sol`, `loader/process.c` | the width is part of the native ABI identity |

**The native ABI carries the word size.** The native runtime ABI names
struct layouts and the boot block, which differ by width, but its number was
the same for both: an rv64 image would have been placed on an RV32 kernel.
RV32 images now declare `FPR_NATIVE_ABI + 500000000`
(`QOS_NATIVE_ABI_ID`), so a kernel refuses an image of the other width by
its first check, before reading any layout. Existing rv64 images are
unchanged.

**31-bit time in System.qa.** RV32's Int is 31 bits, so raw CLINT ticks
(10 MHz) wrap after 107 s:

- Timer.qa (`programs/mods/timer.fpr`) kept deadlines in ticks; it now keeps
  milliseconds from `Sys.uptimeMs`, arms at most 100 s of ticks at a time
  and sleeps a hosted sleeper at most 1,000 s, re-arming the remainder
  through its existing early-fire path.
- `/services/clock` answered ticks and now answers milliseconds since boot;
  System.qa's clock line, and the appjobs, guishell and termapp uptimes,
  read milliseconds. Before the fix the launcher's clock went negative
  ("-1:0-47") on RV32 after the wrap.
- `timer.fpr` and `uart.fpr` changes each needed a new store version pinned
  by `sysep.fpr` (constructor tags are per module version): timer v3.0
  `f11a31ca977152b0`.

**QLog's hashes on RV32.** The tree's QLog already had an RV32-safe chunk
hash, but the pinned store versions (used through `std/fs` by most tests
and by process images) still multiplied by 31 and overflowed. The merkle
combine `hCombine` overflowed everywhere (`a * 1000003`). Both are now
exact modular arithmetic that never forms a value past p (checked equal to
the old functions on 300,000 random inputs plus the edge cases, so disks
read the same on rv64). Five store versions were re-minted by walking what
the tree reaches: qlog v25/v26, fs v9/v10, files v5.

**Also fixed:** `programs/mods/leaseslots.fpr` still added `10000000` to a
millisecond clock (a microsecond literal the deadline cascade's pattern
missed; its pinned store copy was right), giving endpoint operations a
10,000 s default deadline instead of 10 s. `tests/nativeimage.fpr` gained
`unsafe program` (the strict safety pass flagged markers in the pinned
`std/fs`), and the process test apps keep their sums modulo a prime so they
fit a 31-bit Int.

## Checks

- **System.qa on qemu-system-riscv32** (`-smp 2`): boots, opens the QLog
  disk, takes the four permission answers through `con0` and draws the TUI
  app launcher; over four minutes the launcher's clock reads 01:00 to
  04:00 (it went negative before the fix).
- Spectre-84 rebuilt at FP-RISC `0230c8f1` with the new QLog: `ls`,
  `create` and `cat` on the SD QLog, `date` and `hcat` over qlink.
- **`tools/native-image-check.sol`** (new, replacing the retired shell
  driver; `rv64` or `rv32`), each on a fresh QLog disk seeded with images
  built for that width:
  - image: two processes at once, both intact; an image held while a child
    runs and freed after; no images left; memory returned;
  - refusal: a process's storage calls against a full, a dead and a
    killed-mid-request storage actor, a correlated reply, a cancelled
    caller, a real request, and a failing device primitive;
  - width: an image built for the other width is refused with "native
    runtime ABI mismatch" and nothing is placed.

  All three pass on rv32 and on rv64.
- Regressions: the five rv64 native fixtures, `tools/qlink-qemu-check.sol`,
  Portable `storagedeadlines`, `storagebudgets`, `filessvc`, `apppolicy`,
  `appjobs`, `timer`, `timerroute`, `uartroute`.
- `qlogblock` and `qdisk` (Portable) fail to build on missing `unsafe`
  signatures in `std/blockio` and a pinned store module, identically before
  this change (the known safety rot).

## Not done in this step

System.qa still needs two harts (`-smp 1` boots silently); Spectre-84 has
one, which M6 must solve. The RV32 build uses `rv32imac` with atomics,
where Spectre is `rv32im` (no atomics, no compressed instructions); M6
needs the interrupt-masking atomics from the Spectre image. `appkit.fpr`
and `procapp.fpr` still divide raw CLINT reads by 10,000,000 for their own
displays (app-side, they wrap but do not trap).
