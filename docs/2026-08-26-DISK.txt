The disk is meant to be very simple

[METADATA | DATA | SWAP ]
Are the major partitions of the disk.

Data is append only and bounded
Swap is something closer to a circular buffer, where data can be overwritten when it reaches the end, but also append
Metadata can be modified especially the HEAD pointer to the latest log entry's begin

The data is a recursive chunk based system.
Each chunk has a header and body, with a hash
"Files" are just a higher level concept managed by things like System.qa and Files.qa and typically map a URL to an ID
By folding all the chunks with that ID, you can get the file's data

The storage uses page alignment for each log entry with BULK entries for multiple different small chunks
Its quite easy to read and write a log entry as well as compact and GC
because you can just merge chunks, and mark those pages for deletion

The compaction is idempotent

The metadata is intended to be quite simple, with a few things like the version, write flag and commit flag (tells us if the log entry is complete or requires a rollback) and the HEAD pointer to the latest log entry's begin

Uses merkle trees for data chunks when compacting

REALIZED (mods/qlog.fpr, tools/mkdisk.py; proven by tests/qdisk.fpr +
tests/qdisk2.fpr on qosp, and the System.qa boot on virt):

  METADATA  page 0: "QLOG <head> v<ver> w<write> c<commit> d<dataEnd>
            s<swapCursor> m<merkleRoot>".  The commit flag is written
            ahead of every append (head unchanged) and re-set after,
            so a torn write is detected at `ensure` and rolled back by
            truncation at head.  A bare v1 "QLOG <head>" still opens.
  DATA      pages [1, d): the append-only page log, BOUNDED -- appends
            past d are refused.  Chunk headers carry the payload hash
            ("QREC <np> <pl> <url> h<hash>"); BULK entries ("QBLK ...")
            pack many small url chunks into shared pages; folding a
            url's live chunks in log order is the file/stream read.
  SWAP      pages [d, end): the circular page buffer -- writes advance
            a cursor that wraps onto the oldest page.  Reserved for
            actor paging (mods/docsdata: /actorchunks).
  compact   the GC sweep: copies live records forward in order and
            truncates by head; idempotent (same head, same root when
            re-run); mints the merkle root over the live chunk hashes
            into the metadata.

Still open: per-url URActors over the index; crash-safe compaction
(the sweep is flagged w2 in metadata but not yet journaled through
swap); paging actors out to /actorchunks.
