# Editor: a text editor that builds and runs FP-RISC inside QOS

Date: 2026-10-16. Kind: implementation record. Follows the Main Profile apps
([2026-10-16-MAIN-SHELL-APPS.md](2026-10-16-MAIN-SHELL-APPS.md)) and the
compiler bridge (`std/compile.fpr`, `tools/fprd.py`).

## What it is, from the user's chair

**Editor** (`editor.qa`, the sixth onboard app) opens on the last file it had,
or on an empty untitled buffer. It is quiet: a header with the file's name, a
dot while there are unsaved changes, where it lives and the caret's line and
column; numbered lines with the current one lit; a status line that says what
just happened and which keys matter now. FP-RISC (`.fpr`, `.sol`, and an
untitled buffer) is coloured: comments, strings, keywords.

| keys | do |
|---|---|
| typing, Enter, Backspace, Delete | edit; Enter keeps the indentation and adds two after a line that opens a block (`=`, `->`, `of`, `then`, `else`, an open bracket); Backspace in indentation goes back a stop |
| arrows, Home, End, PgUp, PgDn; ctrl with arrows, Home, End | move (Home goes to the first non-blank, then column 0); by word; to the ends |
| shift with any of those | select |
| the pointer | click places the caret, drag selects, the wheel scrolls |
| ^S, ^shift-S | save; save as (a path under `/home/` or `/tmp/`) |
| ^O | open: the files under `/home` and `/tmp`, filtered as you type; Enter opens the one picked, or the path typed (a new file if it is not there) |
| ^N | a new untitled buffer |
| ^Z, ^Y (or ^shift-Z) | undo, redo (typing undoes a run at a time) |
| ^A, ^C, ^X, ^V | select all, copy, cut, paste (without a selection, the line) |
| ^D, ^K, alt-Up/Down | duplicate the line, delete it, move it |
| Tab, ^], ^[ | indent (spaces; a selection's lines), indent, outdent |
| ^F, ^G | find (Enter goes to the next match; the count is shown), go to line |
| ^B | build: the buffer through the host compiler; the diagnostics in the output panel, shown from their start; the caret on the first error's line and column |
| ^R | run: build it, start it as a process of its own, stream what it prints into the output panel; ^R again stops it |
| ^J | show or hide the output panel |

Unsaved work is not lost to a closed app or a reboot: about half a second
after the buffer settles, the Editor keeps a session record
(`/home/.editor/session`: the path, and while there are unsaved changes the
text). Opening it again reopens the file, with the unsaved changes if there
were any ("Recovered your unsaved changes"). A second open or ^N over unsaved
changes asks first. A save cannot lose the text: the worker writes a safety
copy (`<path>.~save`), then the file, reads the file back and compares, and
only then removes the copy; a failure says which of those happened and where
the text is.

The shell gives Tab inside an open app's content to the app (the Editor
indents with it). Shift-Tab always moves the focus, so the shell's Home and
Refresh stay reachable from the keyboard; Esc still goes home.

## Build and Run

Both go to the host compiler daemon (`tools/fprd.py`, started by
`tools/main-profile.py --run` on a private socket and stopped with qosp;
`--no-compiler` runs without it, and the Editor then says "no compiler server").
The daemon's package op builds the buffer exactly as `make plugin-qa` builds an
app: the reply is a relocatable `.qa`.

- **Build** (^B) packages the buffer as written, so it checks modules too.
  It answers "ok (a N KiB package)" or the compiler's diagnostics, with the
  daemon's copy of the source renamed to the buffer's name.
- **Run** (^R) needs a `main`. `programs/mods/runprog.fpr` adds one line to
  the source, after the header (`unsafe program.`, `profile base.`) or first,
  never after the program, where an unfinished last definition would swallow
  it and the error would name a line nobody wrote:
  `qedRun me = go = receive me; _ = drop go; v = main; _ = print v; Unit.`
  Diagnostics are mapped back past that line. The package is attached in the
  Editor's own actor, its `qedRun` is spawned with `Sys.spawnApp` (a fresh
  pid; the image is freed when that pid goes quiet), that pid's console is
  captured, and only then is it told to go, so nothing it prints escapes.
  Every tick (100 ms) drains what it printed into the panel and looks for its
  end: "finished" (and its value, unless it was `()`), a trap's text (with the
  runtime's own `[ERR] actor failed:` line), or "stopped". Closing the Editor
  stops it.

Measured on this Mac (M-series, the daemon warm): a small program packages in
1.0 to 1.9 s into a 130 to 200 KiB `.qa`; attach, spawn and the first output
follow within one tick.

## What changed underneath

**The compile bridge holds no hart (ABI v21).** Until now `Sys.compile` ran
the socket exchange on the calling hart's thread (syscall tag 7), so a
compile of a few seconds froze whatever shared that hart: the shell is on
hart 0, and an app's model actor must answer the shell within 500 ms. The
bridge is now worker-backed like the disk's (`qos/portable/compile.c`): the
HAL table's `compile_submit` copies the request and queues it for one host
thread, and the app-side shim (`qos/appside/entry.c`) parks the calling actor
between `compile_done` polls. A caller killed mid-compile releases its request
through the actor's cleanup hook; the worker frees the job when the exchange
returns. Tag 7 is retired. Checked on one hart: a ticker actor keeps ticking
through a compile (`tests/runprog.fpr`). As with every ABI change, the check
is exact: a device running a v20 bundle (the Pi, the STAR64) takes qosp and
every `.qa` rebuilt together.

**A program's console (`Sys.captureConsole`, `Sys.takeConsole`,
`Sys.releaseConsole`, `qos/appside/hal.c`).** What the actors of a captured
pid print goes to a buffer instead of the host console. The capture belongs to
the actor that made it: only it drains or releases it, and if it ends first,
its resource list releases the capture (a closed Editor leaks nothing).

**The shared app worker** (`programs/mods/appjobs.fpr`) gained `Compile`
(the worker parks in it) and `SaveFile`; `WritePath` became a `replace`-mode
open and one write (it was a delete and then a write: two index changes per
save, and a moment with no file at all), with a 2 s write deadline (was 1 s). Run's
attach is NOT in the worker: every app links the worker, and the loader
(`plug.fpr` with its archive readers) would have grown each of them by about
270 KiB.

**The file namespaces** (`programs/mods/qsys.fpr`) now remember their files.
The manager keeps an index (`sys/files`, one `+path` or `-path` line per
change) and registers every file it lists at boot; a file older than the
index (with records on disk but no line) is adopted the first time it is
opened, so files from earlier boots open, list and delete. An open in the
`replace` mode empties the file first. A path ending `.~save` (the Editor's
safety copy) is transient: it is not written to the index. An empty file
reads as `""` (it used to read as a "(empty file)" placeholder).

**fprd** puts packages and their objects under `$FPRD_BUILD` (`fprd-packages/`,
`fprd-objects/`; they used to land beside the checkout), removes a stale
package before a build, so a failed build can never answer with an older one,
and leaves the build's progress chatter (`use:`, `unit`, `make:`) out of the
diagnostics it returns.

## Bounds

Registered in [2026-09-19-BOUNDS.md](2026-09-19-BOUNDS.md):

- the compile reply's size: **gone**. It had to fit the app's 256 KiB syscall
  buffer ("compiled asm larger than the channel buffer"); the reply is now read
  whole into the host job and copied into the caller's heap.
- `QOSP_COMPILE_WAIT_S` (450 s, `compile.c`): how long the host waits for the
  daemon to say anything, from the daemon's own deadlines (a publication is a
  120 s commit then a 300 s build). Reaching it: `Err "the compiler server
  stopped answering"`.
- `QOS_CAPTURE_KEEP` (64 KiB, `hal.c`): a captured console keeps the last
  64 KiB between drains. Reaching it overwrites the oldest bytes, and the next
  drain begins `[N earlier bytes not kept]`. The reader shows 400 lines; a
  buffer that grew while its reader was busy would let one runaway program
  exhaust the shell.
- the Editor's own: 400 output lines and 200 undo steps (`outKeep`,
  `undoDepth` in `editapp.fpr`), the oldest going first.

## Checks

- `qos/tests-host/compile-check.sh`: the bridge against a fake daemon, built
  with the address and undefined-behavior sanitizers: a 1 MiB reply arrives
  whole, no server is -2, a server that says nothing is -3 (the wait shortened
  for the test), and a request its caller abandons is freed while a later one
  is answered.
- `tests/editbuf.fpr`: the buffer's edits, about 40 checks (`fpr run` on the
  host, or in QOS).
- `tests/appsession.fpr`: the Editor's model through `update`: the session
  record read first; typing undone a run at a time and redone; save-as through
  the safe job; a build error and a run error on the buffer's own line and
  column (the run's mapped past the entry); the session record half a second
  after a change; a recovery. `tests/guishell.fpr` and `tests/shelllayout.fpr`:
  Tab reaches the app's content (a held pointer is cancelled first), Shift-Tab
  leaves for Home.
- `tests/runprog.fpr` (`./qos.py run tests/runprog.fpr --harts 1`, the
  `#: fprd` directive starts the daemon): a compile holds no hart; a program's
  output is captured exactly; a Unit main; a trap ends it with its reason; a
  compile error names the program's own line; a spinning program is stopped; a
  flood keeps its last 64 KiB and says what it lost. HOLDS on 1 and 4 harts.
  `tests/selfhost.fpr` (the package-and-hot-swap loop over the same bridge)
  HOLDS on 1 and 4 harts.
- `tools/guishell-check.py` (real GL, two boots, the viewport sweep; passes
  end to end): the Editor opened, a program typed and saved as
  `/home/calc.fpr` through the save-as prompt, run (`42` and "finished" in the
  panel), a broken line built (failed at line 2), the unsaved change recovered
  after a close and again after a reboot.

## Not done, and why

- **Not isolation.** A program gets no namespace and no grants (the namespace
  refuses its pid), so it cannot open files or services; handing it `/home`
  would mean passing the namespace in its go message and granting it. But
  devices are not gated per process: `device "blk"` would give it the raw disk
  under the system's own disk writer.
- **A stop ends the root actor only.** Actors the program spawned run on (and
  print to the host console once the capture is released); QOS has no
  kill-a-whole-process primitive.
- **Exhaustion is still the machine's.** A program that recurses past what its
  stack can grow to, or exhausts the heap, panics all of QOS: containing that
  per process needs the runtime (`../fprisc`) to fail the process instead of
  the machine.
- **Imports.** The daemon compiles a copy of the buffer in its build directory,
  so `use "std/..."` resolves and a relative `use "../x"` does not.
- **Where there is no host compiler** (a Buildroot image), Build and Run say so.
- **One worker.** A save made during a build waits for the build (a second or
  two); one build or run at a time.
- **Found along the way, not fixed:** `g_sysout` (`qos/appside/entry.c`) is one
  shared buffer for plugin attach errors and the legacy `Sys.storeReq`, unlocked:
  two harts attaching at once could mix their error texts. Compile no longer
  uses it.
