# Main Profile: a small graphical boot shell

Date: 2026-10-03; app contract updated 2026-10-14. Status: Portable GUI prototype.
See [recursive MVU delivery and current evidence](2026-10-14-RECURSIVE-MVU-SHELL.md).

## Try it

```sh
python3 tools/main-profile.py --run
```

The builder reads [profiles/Main.toml](../profiles/Main.toml), builds the shell
and four onboard `.qa` plugins, and creates `build/profiles/Main/Main.disk`
on first use. Subsequent builds preserve that disk. Use a new `--output`
directory for a fresh installed app set; changing the profile does not silently
replace existing application records or user state.

The entry is [programs/main.fpr](../programs/main.fpr), with the shell in
[guishell.fpr](../programs/mods/guishell.fpr). The first screen has rounded
tiles, colored icons, proportional text, selection highlighting and a page
indicator. The viewport determines how many tiles fit each page. The prototype includes Clock, Files, Logs
and About shortcuts plus the existing clock, logs, browser and disk plugins.

Press and release a tile, or use arrows and Enter/Space to open it. Tab/Shift-Tab
move keyboard focus between content and footer controls. Page Up/Down changes
pages. Escape returns home. Clicking the bottom of an open app also returns
home. Q exits from the home grid. P writes a rendered snapshot under
`/tmp/qos-shell-<counter>.ppm`.

The Files and Logs shortcuts use a vertical text pane: separate lines,
word wrapping (including long URLs), a viewport-derived row count and a scrollbar.
Up/Down moves one row; Page Up/Down moves a page; Home/End jumps to the
first/last page. Clicking the scrollbar selects a position. Desktop wheel
events also scroll. A rebuilt Pi host also reports evdev wheel and primary
touch facts; the legacy PS/2 fallback provides movement and clicks. Reopening either
shortcut starts at the top. Logs shows the live normal ring, newest first.

## Discovery and application contract

System composition uses the existing `Qsys` namespace, storage, log and graphics
owners. Main requests automatic display sizing; its viewport determines layout,
page capacity, focus controls and hit regions. Test entries may request an
explicit window size. The disk's `apps/index` supplies app tiles,
and the shared plugin loader attaches the corresponding archives. Adding a
compatible `.qa` to the onboard index needs no shell source change.

Opening an attached plugin validates its root `appMain` export and arity, then
starts an app actor and negotiates a versioned primitive bootstrap with the
exact shared `appwire` schema. Only after agreement does Main send typed
session messages. Each onboard app owns its model, calls its ordinary named
update/view functions, and runs read commands in one persistent owned worker.
Main renders cached scene/text replies. It no longer invokes the legacy
`appInit/appUpdate/appTree/appVals` function table or performs app service reads
inside the compositor.

A malformed or refused archive stays visible with an error. Legacy archives
without `appMain` are refused on launch. Rebuild the shell and all four onboard
archives together; a preserved writable disk needs its app records updated
explicitly. `Close` stops new work, waits for a bounded worker acknowledgement,
and reports confirmed or failed cleanup. R retries read failures or starts a
new failed session within a bounded recovery allowance; Escape returns Home.
The detailed budgets and uncertain-open boundary are in the recursive MVU plan.

Plugins run cooperatively inside the shell process. Unsafe roots have no checked
interface stamp: ABI, scope, arity and schema checks do not certify entry types
or isolate native traps. Arbitrary process-mode archives and native RV64 apps
are not launched by this prototype.

The desktop input tier now additionally reports absolute pointer positions
as kind 7, normalized to framebuffer coordinates. Relative motion remains
available for existing games and console mice. The shell adapter maps pointer
movement and button transitions into its update loop; release and held-button
events do not repeatedly launch tiles. Relative-only input starts at the center
and uses highlighted selection as feedback.

## Main Profile at boot

Build the profile on the target architecture. In Buildroot, enable
`BR2_PACKAGE_QOSP_MAIN_PROFILE` and set `BR2_PACKAGE_QOSP_MAIN_DIR` to the output
directory containing `main.qa` and `Main.disk`. The package installs the shell
as `/usr/share/qosp/app.qa` and the initial application disk beside it. With
autostart enabled, the existing session starts it on tty1.

The session copies the initial disk into writable state only if it does not
already exist, then selects it through `FPR_DISK`. An explicit `FPR_DISK` keeps
precedence. `QOSP_SHARE`, `QOSP_BIN`, `QOSP_APP` and `QOSP_STATE` allow an isolated
session test and deployment overrides. The package sources had been hidden by
the unanchored `qosp` ignore pattern; a specific exception now retains them.

“Main Profile” here means the Portable graphical boot composition. This does
not replace the native `system.fpr` text launcher. The shell and its child apps use
[responsive MVU geometry and input](2026-10-14-RESPONSIVE-MVU-INPUT.md). Multi-touch,
monitor/input hotplug, custom icons, installation UI, application permissions
and independent process switching remain follow-ups.

## Verification

The durable runner is:

```sh
python3 tools/guishell-check.py --output /tmp/qos-shell-check
```

Use a fresh output directory. It builds real archives, seeds an isolated disk,
and opens the actual GLFW graphics backend on macOS, or uses Xvfb on Linux.
It checks two pages, all four onboard apps, session reopening, Browser updates,
return home, malformed/non-GUI archive refusals, later successful app opening,
Files/Logs vertical rows and paging, and a second run on the same disk.
Captures must contain visible label pixels
and differ across the relevant transitions; PPM and PNG artifacts are retained.

The control fixture checks partial pages, page clamping, gaps, pointer coordinate
bounds, relative/absolute events and button transitions. It is in the smoke set.
It also checks scrolling keys, wheel dispatch, scrollbar clicks and limits;
`tests/scrolltext.fpr` checks newline splitting, proportional wrapping,
long unbroken tokens, empty content and bounded visible rows.
The session check exercises initial seeding, preservation and explicit disk
selection using the actual boot script with a recording runner. That verifies
script behavior, not a booted Linux image. The real graphics runner is in
`check-all.sh` with explicit display prerequisites.

Pi hardware, a rebuilt Buildroot image, native graphics, touchscreen input and
the full regression sweep remain separate checks.

Original 2026-10-03 validation on macOS Apple M4: the real graphics runner passed both runs, including
all captures and the session script checks; the control smoke leg passed;
the pre-existing Qsys two-boot test retained its 3-to-6-byte persistence result;
and the actual Terra II/dungeon shared-graphics regression passed. The home,
second-page and loaded-app captures were visually inspected. Live keyboard
navigation and pointer highlighting were also observed through the desktop UI.
The desktop tool reported a locked Mac during the remaining live mouse check;
physical click delivery remains unverified. Press/release dispatch is covered
by the runtime input fixture. No Pi or rebuilt Linux-image boot is claimed.
The shell runner also passed with a fresh app set after the concurrent plugin
compatibility changes moved the Portable ABI to version 18.
