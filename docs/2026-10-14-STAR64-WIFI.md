# STAR64 wireless router connection

Kind: physical hardware and installation record. Added 2026-10-14.
Applies to the installed STAR64 Linux 5.15.131 card, alongside the
[Portable](2026-10-14-STAR64-PORTABLE.md) and
[PowerVR](2026-10-14-STAR64-POWERVR.md) trials.

The board connected to the router using the SSID and password from the ignored
local `qos/.env`. Their values are deliberately omitted from this record.
The existing provisioner's data-only parser read the file without executing
shell code. The WPA2 PSK was derived locally and passed directly over SSH;
the plaintext password was not written into a deployment artifact or printed.

The installed `/etc/wpa_supplicant.conf` is root-owned with mode 0600 and
contains the derived PSK. It remains a secret even though it is derived.
The previous configuration is retained privately as
`/etc/wpa_supplicant.conf.before-router`. No credentials are committed.

The existing `8852bu` driver and `/etc/init.d/S41wifi` are sufficient. After
authentication completed, the wireless interface still held an old
192.168.255.254/29 lease. Restarting its DHCP client acquired the correct
router lease: **192.168.0.215/24**, gateway **192.168.0.1**. Ethernet retains
**192.168.0.151**. Both addresses are DHCP assignments and may change.

Verification:

- WPA state reached `COMPLETED` with WPA2-PSK, and the active network matched
  the local environment file without displaying its name or password.
- Restarting the wireless startup service reconnected and obtained the lease
  from the saved configuration. A full board reboot for Wi-Fi was not needed
  or performed in this trial.
- SSH to 192.168.0.215 authenticated with the existing key and verified the
  board's known host identity, using its existing host-key entry as an alias.
- Ethernet was temporarily disabled under a recovery timer. During that
  interval SSH over 192.168.0.215 succeeded, `eth1` reported `down`, and three
  router pings explicitly through `wlan0` all succeeded. This establishes
  wireless connectivity independently of the Ethernet path.
- Ethernet was restored afterward. The QOS Main service remained running
  throughout the wireless-only test; its graphics service was not restarted.

The network configuration is persistent on the installed card. The saved
Buildroot SD image has not been rebuilt with these private credentials.
Sanitized wireless-only test evidence is under the ignored
`.qos/star64/2026-10-14-wifi/` directory.
