# qos.toml: the project manifest (implemented subset)

Status: implemented 2026-10-29. This is the first slice of the "Project contract" in
[2026-10-28-PORTABLE-APP-WORKFLOW.md](2026-10-28-PORTABLE-APP-WORKFLOW.md). It is a
project configuration file. It is not the archive manifest that `tools/mkqa.py` writes
into a `.qa`, and it is not `fpr build --manifest`.

## What `qos new` writes

```text
myapp/
  app.fpr        # the template's program (the entry)
  qos.toml
  assets/        # .gitkeep; the asset root
  .gitignore     # .qos/ dist/ build/
```

```toml
[app]
id = "myapp"
name = "myapp"
version = "0.1.0"

[build]
entry = "app.fpr"
target = "qos-portable"
```

## What reads it

`qos run DIR` and `qos pack DIR` (DIR defaults to `.`), or `qos run DIR/<entry>`
naming the entry file itself:

| Field | Required | Effect |
|---|---|---|
| `[app] id` | yes | The `.qa` manifest `id`, which names the app's store (`qos-store/<id>.kv`). Validated by the `qos/app_id.h` rule: 1-64 bytes of `A-Z a-z 0-9 _ - .`, no leading `.`/`-`, no `..`. `pack` writes `dist/<id>/<id>.qa`. |
| `[app] name` | no (defaults to id) | The `.qa` manifest `name` (display name). |
| `[app] version` | no (defaults to `"1"`, the previous fixed value) | The `.qa` manifest `version`. |
| `[build] entry` | yes | The program, relative to qos.toml. |
| `[build] target` | no | Only `"qos-portable"` is accepted. |
| `assets/` (directory, not a field) | no | `run` sets `FPR_ASSETS` to it (unless a `#: music` directive already does). `pack` copies its files beside the `.qa`, which is where the host looks. |

Precedence for the artifact name in `pack`: `--name`, then `[app] id`, then the `#: name`
directive, then the file stem. The `#: expect` / `#: plugins` / `#: host` directives in the
program are unchanged.

Without qos.toml (an existing app, or a file in this tree), nothing changes: the id and name
are the file stem and the version is `"1"`.

## Deliberately not implemented

- `[app] kind`: the workflow doc proposes `kind = "desktop"`, but there is no desktop adapter
  yet, and the current templates are console/MVU programs. `qos new` therefore does not write
  `kind`, and a `kind` key is ignored.
- Asset declarations, permissions and resource requirements: the workflow doc defers them
  "as their public contracts are defined". Today the only asset convention is the `assets/`
  directory.
- The doc's `main.fpr` entry name: templates keep `app.fpr` so that existing commands and
  docs (`qos run myapp/app.fpr`) still work. `entry` makes the file explicit.
- `build/<app-id>.qa` output and `fpr build --target=qos-portable`: builds still go to
  `.qos/` and `dist/` through `qos run` / `qos pack`.
