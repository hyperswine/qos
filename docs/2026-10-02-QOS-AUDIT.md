# QOS audit against the reference-OS ideal

Date: 2026-10-02. Kind: source audit, with a fresh Portable smoke run.

Audited QOS revision: `b8821e6` (main). FP-RISC dependency: pinned
`d1a25e4` (`fprisc.lock.json`); fprisc HEAD `edfbaac` differs from the pin
only in compiler and tool files, not in `runtime/actors.c`, `fpr.h`,
`buddy.c` or `std/actor.fpr`. Nothing is fixed by this report.

This page follows [the September 29 audit](2026-09-29-QOS-ARCHITECTURE-AUDIT.md)
and records what the September 30 to October 2 batches changed and what
they did not. Line numbers are as of the revisions above, with one
exception: running `./qos.py build` for this audit let the compiler
normalize `programs/mods/svc.fpr` (eleven stamped `route`, `dispatch` and
`dDisp1` signatures collapsed to one each) and re-pin the `svc` hash in
`programs/mods/qlog.fpr`. `svc.fpr` references below are to that normalized
file; in the committed file they sit up to 19 lines later (`dispatch` at
205, `uartRpc` at 272). Neither change is committed by this report.

## The ideal

Stated by the owner, used as the yardstick:

- URLs name everything. `/dev/display` and `/dev/display/0` are both
  addressable like paths at a UNIX-like CLI, but there are no directories,
  only a logical namespace, as in Plan 9.
- `open`, `read`, `write`, `close` are the four primitives and the foundation
  of everything else. No `ioctl`, no `seek`, no special files, no sockets
  built in; those are library abstractions.
- IPC is actors plus URLs. Open a connection to a service by URL; System.qa
  sets up a bidirectional link; afterwards the two ends talk directly.
  Everything is non-blocking message passing.
- ACBs are the scheduling unit. Per-hart schedulers, work stealing, a simple
  run queue, ready queue and backlog, a randomized weighted algorithm with
  upper bounds. No global scheduler.
- A driver belongs to one service. UART.qa owns the UART driver and spawns
  one actor per device at `/services/uart/0..N`. Drivers are FP-RISC over
  small C HAL functions, not raw memory and bit operations.
- Boot is minimal: set up the HAL, then System.qa, Memory.qa, Files.qa,
  Graphics.qa take over as services.
- QOS Portable is the host-testable version and is mostly self-contained.
- Full applications such as Terra II run simultaneously on the OS.

## Verdict

The September 30 to October 2 batches fixed the correctness defects the
previous audit ranked highest: RPCs are correlated and report refusal and
death, native process images are relocatable buddy blocks freed on pid
quiescence, Portable plugins bind by name with no slots, and both disk tiers
park the actor instead of holding a hart. The Portable smoke suite passes
12 of 12 on this tree.

The architectural distance to the ideal is unchanged. There is still no
`open`, no `close`, no connection object, and no single URL resolver; a new
service cannot register a URL without editing System's dispatch chain; the
UART service does not own the UART; Memory.qa, Files.qa and Graphics.qa do
not exist as services; graphics is a 1,500-line C renderer that one app at
a time drives; stealing is donation into a global ring under a lock; the
admission bound is counted in admissions, not time. Portable still hosts one
fixed-address application whose launched plugins are never freed.

The honest summary is: the primitives are now reliable, but the uniform
contracts the ideal is built from have not been written yet. Every path
that exists works; the problem is how many paths there are.

## What changed since September 29

Fixed, with evidence:

- RPC correlation and failure honesty. All Portable services, `std/fs`,
  `std/loader`, `std/uart`, `std/timer` and System's `uartCall` use
  `std/actor`'s `call`, `awaitReply`, `reply` and `sendAwait`
  (`fprisc/std/actor.fpr:93-144`). Dead or refusing services yield `Err`
  (`programs/mods/qsys.fpr:77-85`, `appkit.fpr:51-52`, `std/fs.fpr:35-36`,
  `programs/system.fpr:999-1005`). `fileWr` no longer caches a failed write
  (`qsys.fpr:202-229`).
- Native process images are buddy blocks. `buddy_alloc` per image, RELOC
  applied, non-relocatable refused by name, image registered before the root
  spawn, freed only when `fpr_pid_live(pid) == 0` from the reaper
  (`loader/process.c:121-129, 222-263`; `fprisc/runtime/actors.c:697,
  2661-2671`). Both High findings of the previous audit are closed by
  construction. `tools/nativeimage-check.sh` proves two images at once and a
  lingering child holding its image.
- Portable plugins bind by name. No `PLUGSLOT`, `plugsyms` or shell stamp;
  imports resolved against an export table, missing names refused
  (`qos/appside/entry.c:89-160`; `tools/plugimports-check.sh`).
- Disk no longer holds a hart. Native `hal/virt/blk.c` parks 200 µs between
  polls with deadlines and fail-stop (`blk.c:346-355`); Portable moves
  `pread`/`pwrite` to a worker thread and the actor parks between
  `blk_done` checks (`hal/unix/blk_raw.c:161-215`, `qos/appside/hal.c:214-233`).
- Display in O(1) memory, launcher idle fixed, typed vectors, zero-based
  positions. None of these touch the contracts audited here.

Unchanged: every item in the Scorecard marked Missing, the router's prefix
chain, the QSys boot-only registry, the UART ownership inversion, the
donation ring, the admission-count bound, the C memory fast path, the one
global GL context, and the single fixed-address Portable app image.

## Naming and the four operations

Seven mechanisms resolve names today, with no shared grammar:

1. Native System router: a hardcoded `prefixOf` chain over eight prefixes
   (`programs/mods/svc.fpr:185-203`), plus `/services/keypad` and
   `/services/apps` handled outside it (`programs/system.fpr:477-481,
   740-744`). Adding a route means editing `dispatch` and the `Caps` record.
2. Portable registry `sysActor`: an exact-string list written once at boot
   with `/services/vfs`, `/services/log`, `/services/storage`
   (`qsys.fpr:146-166, 452-454`). `svcLookup` has no callers in the tree.
3. Portable VFS `vfsActor`: `(path, kind, owner)` entries, create-on-write
   only under `/tmp/` and `/home/` (`qsys.fpr:280-365`). No API lets an app
   add an entry. The permission gate is documented as not enforced
   (`qsys.fpr:35-37`).
4. `device "<name>"`: a C string table (`uart`, `clint`, `blk`, `net`),
   used from 23 call sites including Terra II, POS, the desktop demos,
   LiveView and FPRLive.
5. QLog record keys without a leading slash (`apps/index`, `apps/<id>.qa`,
   `sys/live`, `sys/boots`), equal to VFS paths only by convention.
6. Loader and manifest ids (`LLoad id`, `apps/{id}.qa`).
7. The foreign surface: 34 names in `core/foreign.fpr:23-63` and 31 table
   slots in `qos/appside/qos_abi.h`, reached by linking, not by URL.

`/dev/display` or any `/dev/` path: not found in `programs/`, `std/` or
`core/`. The display is `/services/display` natively and a direct `glRender`
call on Portable.

Of the four operations, only read and write exist as shared verbs
(`svc.fpr:335-338`; `appkit.fpr:42-43`). There is no handle, no per-client
state, no cancel and no close. UART's `open`/`close` are UART-specific linear
phases (`std/uart.fpr:82-85, 155-156`). File actors are created lazily and
never end (`qsys.fpr:253-257`). `VfsList` is a separate verb rather than a
read of a namespace URL.

Operations outside the four fall into two groups. Library protocols over an
actor handle, which fit the ideal in shape: QLog's latest, append, replay,
tombstone, stats, compact, bulk, verify; the loader's load, list, replay,
launch; UART's params, buffer, arm, flush, subscribe, share; timer's
`TAfter` with a pushed `TFire`. Primitives that bypass the URL and capability
model entirely: `glInit`, `glRender`, `inputPoll` (every GL app through
`glsvc.fpr:63-89`), `sndPlay` and `sndMusic`, `netPoll` through `netClose`
(FPRLive, LiveView), `blkPages` with each app spawning its own storage actor
over the raw device (`terra2.fpr:2073`, `pos1.fpr:659`, both desktop demos),
`Pin.*`, and `reg32` on the CLINT for time in six programs.

## IPC and blocking

Receive always parks: `receive`, `receiveFrom`, `receiveRes` and
`receiveFromRes` go through `block_unless` (`actors.c:1630, 2292-2470`). Send
never waits and answers refusal or death as a `Result` (`actors.c:2161-2246`).
That foundation is right.

"Open then talk directly" holds only where a client already holds an actor
id: registry-owned services on Portable, and the timer, UART and storage
actors inside the native capability record. File traffic goes app, VFS,
relay, Files, file actor on every call; native `Svc.read` and `Svc.write`
re-run the prefix chain on every call. Bidirectional push exists in two
places: UART `USub` and timer `TFire`. `USub` is not reachable through the
shared `/services/uart` route, so only an app that spawned its own UART
actor gets RX pushed. Keyboard input is poll-only on both sides.

Mediator head-of-line blocking is unchanged: `vfsServe`, `filesFwd` and the
loader loop wait on a downstream reply before taking the next request
(`qsys.fpr:244-248, 281-289, 362-365`). One stalled file or storage actor
now stalls every namespace client for up to the 5 s disk deadline.

Hart-holding paths still present:

| Path | What holds the hart |
|---|---|
| `hal/virt/net.c:219` | `nic_tx` spins up to 4,000,000 iterations for TX completion, on every `netWrite` |
| `qos/portable/haltab.c:54`, `hal/unix/net_raw.c:273` | console `write(1, ...)` on a descriptor never set non-blocking |
| `fprisc/machine/virt/hal.c:52` | per-byte THRE poll, used by every `/services/display` write |
| `hal/unix/gfx.c:1412` | `glfwSwapBuffers` under vsync, on the calling hart |
| `fprisc/runtime/actors.c:751-753` | `xpush` spins when a cross-hart wake ring is full |
| `fprisc/runtime/actors.c:2167` | the deep copy in `fpr_send_as` runs unpreempted |

Disk is suspension by timed poll, not completion by message: 200 µs sleep
loops, one outstanding native request, one Portable worker. A fail-stopped
storage actor is never restarted; clients see `Err "dead actor"`.

Unchecked or uncorrelated sends remaining on the native plane:

- `svc.fpr:253-256` `uartRpc` ignores the send result and uses an
  uncorrelated `receiveFrom`; every `/services/uart` route can hang on a
  dead UART actor.
- `svc.fpr:216-217` `dTimerW` discards a refused `TAfter`; the tick is lost.
- `loader/process.c:69-75` `send_or_die` retries 1,000 times then panics
  the machine on refusal; `qos_store_call` waits with `receiveRes` from any
  sender (`process.c:158`).
- `system.fpr:670` `runProcessShared` takes the next `Result` from any
  sender as the process exit.
- `fpr_actor_fail` panics the whole machine for a routed process image
  rather than killing the actor (`actors.c:1752`).

Polling where events belong: `getcW` yield-polls the UART line-status
register (`system.fpr:63-68`, `svc.fpr:165-170`), the launcher polls at
1 kHz (`system.fpr:806-813`), FPRLive's idle turn polls at 10 kHz
(`fprlive.fpr:464-472`). `sendSure` yield-loops without bound against a
saturated live receiver (`fprisc/std/actor.fpr:49-68`).

## Scheduling and memory

Per hart: a FIFO run queue of capacity 4, a ready backlog list, an LCG, a
sleeper list (`fprisc/runtime/fpr.h:271-302`). Selection is one pass over
the backlog, aging candidates when `g_adm - ready_at > g_tau` or `prio`,
otherwise weighted reservoir sampling; aged wins (`actors.c:890-926`). This
is the simple randomized weighted policy the ideal asks for.

Global state exists. `steal_ring[64]` under `steal_lock`, the machine-wide
admission clock `g_adm`, and the deadlock-detector counters
(`actors.c:785-794, 668-670`). Balancing is donation: a hart whose backlog
exceeds 4 walks it for the oldest unpinned ready actor and pushes it into
the ring; an idle hart pops the ring (`actors.c:813-856`). No hart reads
another hart's queues, so this is a shared pool, not victim stealing, and
the only migration path is through the pool. The lock is held for O(1).

The bound is `FPR_TAU = 64` admissions. Selection is O(backlog) per
admission, so one refill is up to four full scans. The comment claims
`Wait(a) <= tau + k * T_slot` (`actors.c:764-766`); nothing enforces
`T_slot`, and the referenced `docs/SCHED-MODEL.md` does not exist in the
fprisc tree. Preemption is compiler-inserted fuel at function entry,
2,000 entries per slice (`compiler/Codegen.hs:96-115`; `actors.c:86,
1490-1498`); C entries never preempt (`fpr.h:258`).

Memory is one global power-of-two buddy with a 64 KiB minimum block and one
spinlock (`buddy.c:1-20, 61-88`), which matches the ideal. Allocation is
not actor-mediated: `fpr_mem_take` tries `buddy_alloc_try` inline and only
posts to the C memory actor on contention (`actors.c:2722-2743`). There is
no FP-RISC Memory.qa and no per-actor memory budget; `Static n` and
`Dynamic n` size the mailbox ring only (`actors.c:79-83, 1951-1985`).

Mechanisms beyond the three queues, all real surface: the donation ring,
the hart-0 deadlock detector on a 30 ms tick, spin-before-block and
spin-before-park windows, per-ACB transition traces and panic guards,
channel-block epoch limbo, growable stacks with a recycler, seven SPSC plus
one locked MPSC ring per actor, IRQ-hart designation, the memory actor
bypass, the code-publication fence counter, and the `fpr_sched_t` routing
table for process images (`actors.c:170-213, 559-663, 986-1000, 1182-1187,
1343-1352, 1604-1628, 2825-2843`).

## Drivers, HAL and boot

Machine boot is minimal: FPU and stacks, BSS clear, `fpr_rt_init` (hart
init, buddy, actor 0, the memory actor), `fpr_hart_main`, then
`system.fpr` `main` as actor 0 (`fprisc/machine/virt/crt0.S:21-53`;
`runtime/runtime.c:98-126`). Portable is equally tight: `qosp.fpr` runs
init, read archive, parse manifest, ABI gate, hash gate, permission gate,
load, run, with three C seams (`qos/portable/qosp.fpr:57-128`;
`host.c:303-446`).

Everything above `main` is a monolith. `programs/system.fpr` makes raw
console registers and prints banners (`:949-957`), initializes the process
arena, spawns UART, timer and storage in a fixed script (`:989-1022`), owns
manifest and grant policy, the permission UI reading keys off the console
(`:189-213`), persisted decisions, capability construction, the router,
process placement, and the shipped TUI apps themselves (`:676-918`).

No Memory.qa, Files.qa, Graphics.qa or UART.qa exists as a loadable
service. The `.qa` archives built from `apps/*.toml` are name-dispatch
placeholders whose code is co-compiled into the kernel image
(`tools/mkqa.py:20-23`; `system.fpr:676-679`). `host.c:27-29` states there
is no System.qa or Memory.qa process tier on Portable.

Ownership violations, current:

- Console TX and keyboard RX go to 16550 registers directly from the router
  (`svc.fpr:150-173, 258-271`) and from System (`system.fpr:33-68`). The
  UART service is spawned unarmed and shared (`system.fpr:984-995`), so the
  named owner deliberately does not own RX. The runtime's panic path and
  logs write the same UART behind every actor's back.
- `fpr_g_blkRead` and `fpr_g_blkWrite` are exported to any native program
  (`hal/virt/blk.c:373-389`) and any Portable image (`qos/appside/hal.c:264-266`).
  QLog's single-writer property is a convention.
- `net*`, `Pin.*`, `glInit`, `glRender`, `inputPoll` and `reg32` on the
  CLINT are plain foreign functions. The Portable device lookup checks table
  support, not ownership (`hal.c:141-166`).
- `hal/unix/gfx.c:276-306` holds one static `G` with the window, context,
  FBO, meshes, DRM link and the event ring; `glsvc.fpr:13-16` relies on
  being the only caller by comment.

No per-device factory: `uart.fpr:53,133` and `timer.fpr:44` name their
device and IRQ inside the actor, so a second instance would open the same
device. `/services/uart/<n>` does not exist and would need a new dispatch
branch.

HAL abstraction depth is mixed. `hal/virt/plic.fpr` and the pin-bus drivers
(`bbspi`, `matrixkpd`, `ttp229`, `oled`) are the typed-layout,
inject-the-primitives style the ideal describes. `uart.fpr` does DLAB
sequencing, shifts and bit tests by hand (`:57-58, 154-157, 217-219`).
Policy living in C: the ARP, IPv4 and TCP stack (`hal/virt/net.c:12-16`),
the scene walker, mesh generators, text staging, sorting, camera math and
key mapping in `gfx.c`, the KMS probe in `drm_scanout.h`, MP3 decoding and
mixing in `snd_raw.c` and `minimp3.h`, input source priority and escape
decoding in `tty_raw.c`, and the disk deadline and fail-stop policy in
`qos/appside/hal.c:211-236`.

## Portable and simultaneous applications

Portable's headless host is libc and pthreads on Linux; macOS always links
AudioToolbox (`qos/Makefile:43-44`). GL enters only the `portable-gl` and
`portable-es` targets. Building anything needs the GHC-built `fpr` and
Python for `mkqa`, `mkexports`, `mkimports` and `mkdisk`.

The `.qa` container has three load profiles: the Portable app is a
fixed-base, non-relocatable image at `QOS_SLOT_BASE` (`host.c:5-6, 358`;
`qos_abi.h:52-56`; `qos-app.mk:51-56`); Portable plugins are relocatable
with an import table; native processes are relocatable with a whole runtime
copy and no import table. `tools/mkqa.py:253-258` makes relocation opt-in.

Portable launched apps are never freed. `entry.c:199-205` registers each
attached image as pid 0 with the comment that a plugin is never unloaded;
`std/loader.fpr:113` re-attaches on every launch; no `fpr_pid_quiet` is
installed on the Portable side. `tests/apps.fpr` passes its memory check
because the tolerance is 97% and the images are small (`apps.fpr:46-50`).
The native half of "images are ordinary managed memory" is done; the
Portable half is not.

Simultaneous full applications are not established. Terra II spawns its
own GL actor over the one global GL context (`terra2.fpr:2072`;
`gfx.c:272-290`), as does the dungeon. No module provides a shared Graphics
service, a compositor, window arbitration or focused-input routing; the
`appUpdate` focused-key contract has no dispatcher left in `programs/`.
Portable input is one HAL poll consumed by whoever polls. Native processes
each read the 16550 directly for `/services/keyboard`, so two would contend
on the device. The native launcher is serial (`system.fpr:674-681,
854-860`). No test anywhere starts two GL services or two graphical apps.

No single application codebase runs on both sides: different build rules,
different process ABIs (`entry.c` versus `proc_entry.c`), `Sys.spawnApp`
refused on native (`actors.c:2060`), and no native graphics or sound HAL.
Terra II, POS and the dungeon run on Portable only; the TUI launcher and
console apps run on native only.

The September order still applies. Updated for what has landed:

1. Close the findings table. The net TX spin and the Portable image leak
   are the two that contradict already-documented properties.
2. Write the endpoint contract once: resolve and authorize at `open`,
   return the owner's actor id, direct traffic afterwards, `close` and
   cancellation, refusal and peer death as messages. Decide that directory
   listing is a read of a namespace URL rather than a separate verb.
3. Replace the router's prefix chain and the VFS boot list with
   registration by the service. The acceptance test is a new service
   claiming a URL with no edit to System or QSys.
4. Make UART.qa own the UART: console and keyboard become `/services/uart`
   messages, System stops making a raw console, device and IRQ are injected,
   and the service spawns `/services/uart/<n>` per device.
5. Pull graphics apart: small C primitives (upload, draw, present, read
   pixels) under one system-owned Graphics.qa that holds the context and
   routes focused input. The acceptance test is Terra II beside a second
   graphical app, either closed and restarted while the other runs.
6. Make Portable's app image relocatable like its plugins, so one load path
   remains and the fixed slot leaves `BOUNDS.md`.
7. State the scheduler bound in time with its assumptions, and decide
   explicitly whether the donation ring stays.
